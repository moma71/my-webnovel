💡 Hands-On Tutorial: 도진의 Cascade Model

Real-world situation: 도진은 576명을 15명으로 관리해야 합니다. 수학적으로 불가능합니다. 그래서 '계단식 확산(Cascade Model)'을 씁니다. 동시가 아닌 순차적으로.

Copy-paste prompt:

나는 {규모, 예: "576명"}의 대규모 변화를 {리소스, 예: "15명의 팀"}으로 관리해야 합니다. 동시에 모두 진행하면 리소스가 부족합니다.

현재 상황:
- 대상 규모: {규모, 예: "9개 지점, 576명"}
- 가용 리소스: {리소스, 예: "15명 팀, 4주 기간"}
- 리소스 배수: {배수, 예: "이전 대비 2배"}
- 작업 배수: {배수, 예: "이전 대비 3배"}
- 수학적 불가능: 리소스 < 작업

제약:
- 동시 진행 불가 (리소스 부족)
- 품질 저하 불가 (실패 시 전체 위험)
- 기간 연장 불가 (데드라인 고정)

목표:
- {기간, 예: "4주"} 안에 전체 완료
- 품질 유지
- 리소스 효율 극대화

다음 형식으로 Cascade Model 전략을 작성해주세요:

1. Phase 구분
- 몇 개 Phase로 나눌 것인가
- 각 Phase 기간과 범위

2. 우선순위 기준
- Phase 1에 어떤 대상을 넣을 것인가
- 선정 기준 (난이도, 중요도, 리소스)

3. Cascade 메커니즘
- Phase 1 → Phase 2 전환 조건
- 중첩 여부 (Phase 1 끝나야 Phase 2 시작?)

4. 리소스 재배치
- Phase 완료 시 인력 이동 방법
- 동시 운영 최대치

5. 리스크 관리
- Phase 1 실패 시 대응
- 병목 지점 식별

실행 가능하고 구체적으로 작성해주세요.

What you'll get:
Cascade Model 전략이 Phase 구분, 우선순위, 메커니즘, 리소스 재배치, 리스크 관리로 구조화됩니다. 제한된 리소스로 대규모 변화를 순차적으로 관리하는 실전 계획을 얻을 수 있습니다.

  • [ ] 실행 후 5단계 전략 확인

🎯 Learning Concept: "리더는 함께 뛴다"

Level 5 Concept: Leadership by Example (솔선수범)

도진은 평택이 힘들다는 소식을 듣고 직접 갔습니다. 총괄 팀장이 현장에 투입된 것입니다. 그는 전략만 짜는 사람이 아니었습니다. 필요하면 작업복을 입고 함께 뛰는 사람이었습니다. 이것이 진짜 리더십입니다. 명령이 아닌 함께함으로 이끄는 것.

Why it matters in 조직 변화:
팀이 힘들 때, 리더가 사무실에만 있으면 신뢰가 무너집니다. 하지만 리더가 현장에 나타나면, 팀은 "우리 함께 싸우는구나"를 느낍니다. 그때 진짜 팀워크가 시작됩니다.

Remember (도진의 행동):
"제가 도울게요. 오늘, 내일 제가 여기 있을게요."
